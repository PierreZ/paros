# paros-model

The pure folds and data types every upper layer shares: the registry, tenants, the fleet directory, tags, placement, footprints, status, views, load, checkpoints and the machine's data types. No I/O, no client, no machine; it imports only `paros-core` and `paros-wire`, and builds for wasm32.

A layer of the library (#722 (three products)): it depends only on the layers below it (root *Layout*). Programs use it through the facade, `paros::model`.

## Map

- `address.rs` → `Address`, `Names` → a machine's advertised `HOST:PORT`, kept as written (a literal or a name), and the one resolver its dialers share; a name is resolved at dial time (#257).
- `machine.rs` → `MachineFacts`, `CellPlan`, `Class`, `ControlJournals` (the cell's, the election journal, the fleet's, one type for driver and client, #243, #240) → a machine's facts (no peer: a machine is configured with none, #277) and its cell's plan, the value of `cell init`'s decree (every identifier drawn by the machine that drives it).
- `machine/cache.rs` → `CachedRegistry`, `CacheSink`, `spawn_writer`, `starting_book` → the durable cached registry fold (#211): the cell's address book at one registry position, in the file `registry` beside the record; written forward only by a task beside the machine; read at every start, so a machine dials moved machines where the cache says (a hint: a wrong address costs liveness only).
- `machine/book.rs` → `address_book`, `cell_book` → the cell's address book (#349): the founding members at the address the registry holds for them, else the plan's; `cell_book` adds every registered machine not retired.
- `machine/record.rs` → `MachineRecord`, `journal_config` → the machine record's text (identity, class, capacity, zone and rack; the decree's acceptor state: `promised <round>/<node>` and the vote `plan <cell_id> <round>/<node>`, written after the stores, the commit point) and a plan journal's `Config`.
- `checkpoint.rs` → `Checkpointable`, `Folder`, `Checkpointer`, `CheckpointRecord` (`MAGIC`, `Begin` / `Chunk` / `End`), `run`, `load` → checkpoint and truncate for any journal owner (#230): a checkpoint is a run of small records committed by its `End`, written in batches a node's `TooLarge` splits; a run with no valid `End` is never restored (#353); `Folder` is also the registry follower's fold.
- `view.rs` → `Scope`, `authorize`, `CellFacts`, `cell_view`, `tenant_view`, `universe_view`, `within_tenant_scope` → the administrative views (#399): pure answers from one cell's folds, filtered by the caller's scope (an admin sees every detail; a tenant scope sees only its own tenant and, of each machine it uses, the name, its `paros/zone` and `paros/rack` tags and up state). `authorize` is the Authz seam until #192.
- `status.rs` → `Word`, `Member`, `judge`, `observe`, `placed`, `Hysteresis`, `fill`, `Summary`, `summarize` → the status words (#191 (status), §3.6): Healthy (the desired shape, every member up and staying), Degraded (both phases keep a live quorum), Unavailable; judged through the placed `AcceptorConfig`'s quorum predicates from a view's own machines; a new word shown only once it held for the window; `summarize` is `parosctl status`'s counts.
- `authz.rs` → `Authz`, `Request` (`keys`: the universe entry's root keys, which rule once read, #245 (Biscuit tokens)), `Target` (`Users` by name, or `Internal` by ids), `Operation` (`FormCell`, `Admit`: an idle machine's calls), `Denial` (`of_label`) → the authorization port; `paros-authz-biscuit` implements it, and Biscuit never enters this crate.
- `load.rs` → `Busyness`, `DiskBusyness` → how busy a machine and its disk were over one window (#424): pure arithmetic over two moonpool `SystemSample`s, FDB's ratios; a counter that went back gives no window.
- `balance.rs` → `Balance`, `Bounds`, `Rebalance`, `ABANDON_ROUNDS` → the pure balancer (#687 (rebalance a cell), §3.4): one watch round over the registry, its storage machines and a `stays` predicate names at most one acceptor booking to move off the most loaded machine of a zone, after a gap above `spread` held for `rounds` rounds; nothing while the cell repairs; one at a time, abandoned after `ABANDON_ROUNDS`. The tenant coordinator wires it (`cell/campaign.rs`).
- `placement.rs` → `plan`, `machines`, `Machine`, `Want`, `Step`, `Shortfall` → the pure placement function (#212 (placement), §3.4): the steps (book, release) that make a target hold its count; class (no capacity, #837 (remove role slots)), no machine with two storage instances of one target, zones in round robin, least busy then least loaded inside a zone (`Machine::busy`, `busy_step`, `with_busyness`), zones that tie by their mean load, ties by a draw seeded with the tenant id, machines marked down last, and only a machine that serves the cell (a founding member, or one `MachineAdmitted`, #511 (placement books machines that never served)); a release takes down machines first, then the most loaded. `zoned` labels a planned membership with its machines' zones and `zone_rule_binds` says where the zone rule binds (`F >= 1` over three zones or more); the tenant coordinator redraws a plan that breaks it up to `ZONE_DRAWS` times, then records the create `Unplaceable` (#215 (zones)).
- `footprint.rs` → `Footprint`, `BIRTH`, `plan`, `fix`, `Fix`, `Shortfall` → a tenant's minimum footprint (#476 (tenant footprint), §3.4): an acceptor quorum, a control-journal quorum and the matchmaker set on storage machines, plus one coordinator slot on a live `stateless` machine when one has room; `plan` books it whole or names the shortfall; `fix` takes one step (place or re-place the coordinator, book a missing slot, leave a draining or unregistered machine). Pure.
- `name.rs` → `JournalName`, `Abbreviations`, `match_prefix` → names at the edge (#239): `paros://<tenant>/<journal>` (and `<tenant>/<journal>`) parsed and printed; ids printed as short hex, git-style (at least 6 digits, widened until the listing is unambiguous); a unique hex prefix matched among a listing's ids. Pure, wasm-safe.
- `tags.rs` → `Tag`, `Tags`, `UserTags`, `Selector`, `TagError`, `reserved`, `value_of`, `is_reserved`, `MAX_TAGS` → key:value tags (#575 (key:value tags), §3.7): a key of at most 63 bytes, a value of at most 255, 32 per entity; a `paros/` key is reserved, written only by its own command; `UserTags` refuses one; a selector (`k`, `k:v`, `tenant.k:v`, comma-separated, all must match). Pure, wasm-safe.
- `fleet/buckets.rs` → `BUCKETS`, `bucket_of` (CRC16-XMODEM of the name mod 16384, Redis Cluster's), `BucketRange`, `BucketTable`, `Placement` (bucket or override with a reason) → tenant placement across cells (#713 (bucket placement)): the first cell takes every bucket, `AssignBuckets` moves a range (refused while a bucket-placed tenant lives elsewhere), a bucket-placed `RegisterTenant` must name its bucket's cell, a cell with buckets is not removed; `FleetDirectory::select_cell` is `--cell-selector` (#672 (cell tag selector)); metadata version 6.
- `fleet/keys.rs` → `RootKeyEntry`, `RootKeys` → the universe entry's root public keys (#245 (Biscuit tokens)): `AddRootKey` and `RemoveRootKey` judged at apply, a key id and a label never reused, the last key never removed; checkpointed with the directory (metadata version 3).
- `fleet.rs` → `FleetEntry`, `FleetCommand`, `FleetDirectory` (`label`: a tenant's display label, its name or `universe` / `cell`, #239), `FleetEvent`, `FleetDirectoryRefusal`, `TenantKind`, `Movable`, `CellKind` (the reserved tags `paros/kind`, `paros/role`, `paros/movable` and a cell's kind and regions, #575 (key:value tags); a cell tenant is always pinned), `SetTenantTags`, `SetCellTags` (user tags, once per request id, `tagged`), `CellState`, `TenantState` → the
  fleet tenant's pure fold, the fleet directory (#229): the fleet, cell and tenant entries (a cell with its entry endpoint; `RemoveCell` removes an empty `REMOVING` cell and tombstones its id, metadata version 5, #232 (multiple cells)), every entry fenced by its
  fleet id and metadata version, ids checked at apply, `Checkpointable`.
- `tenant/scrub.rs` → `ScrubProgress`, `ScrubCounts` → the scrubber's progress record (#362): a cursor (`pass`, `done`, `journal`, `next_slot`) the fold orders records by, this pass's counts, the totals, `late`.
- `tenant.rs` → `TenantCommand`, `ConfigureTarget`, `TenantControl`, `TenantEvent`, `Desired`, `Durability` (`survive_machines` over `partitions`, #523), `StoreDurability` (`Ordered` or `Batched`, the store's commit protocol, fixed at create, #599 (durability mode per journal)), `Survives`, `CellKind` → the pure fold of a tenant's control journal (#210): `Describe` once, `CreateJournal` (with its birth tags and its store durability) / `DeleteJournal` / `SetJournalTags` (#575 (key:value tags)) / `Unplaceable` (#212 (placement); an empty name is a configure's refusal) / `Configure` (a live journal's desired mode or the tenant default, #214 (tenant modes)) per request id, `Placed` (the configuration in force, what views show; the create's `config` stays the bootstrap one), `Scrubbed` (the scrubber's progress, #362; one behind the fold's is `ScrubBehind`), `IdTaken` records nothing, `Checkpointable`; `TenantRoles` (`frontends`, at most `MAX_ROLE_COUNT` = 64), set by a `Configure` of the tenant default and checkpointed (#604 (role counts)); a journal's `replicas`, `proxies` and `batchers` are in its `Desired` (#753 (per-journal proxies)).
- `registry.rs` → `SystemCommand`, `Registry`, `HostedTenant`, `Role`, `BookingTarget`, `Liveness` → the pure fold of the registry (the cell tenant's control journal, #235); `HostTenant` records the tenant's control journal, name and `survives` (#210); the registry is keyed by `node_id` with class, capacity, the RPC incarnation (with the address, the machine's `InterfaceRef` identity) and bookings keyed by role of a journal or matchmaker set (#211: one live booking per node, target and role; a booking id is never booked twice, `spent` kept across checkpoints); liveness `MachineDown`/`MachineUp` and `MachineSlow` (#361 (slow machines): `Liveness::slow`, `SlowFacts`, `is_slow`, `keeps_roles`), changes only (`LivenessUnchanged`, `StaleIncarnation`); maintenance windows (`Maintenance`, `MaintenanceScope`, #359), checkpointed; `MachineAdmitted` and `Registry::serves`, the machines placement may book (#511 (placement books machines that never served)); `GrantCapacity`, a set of slots booked all or none under a `GrantKey` (`Footprint(tenant)` or `Request(id)`), the first grant under a key deciding it, and `HostTenant` refused `NoFootprint` without a granted footprint (#476 (tenant footprint)); `BookingTarget::Tenant`, a tenant-level slot; `Checkpointable` (#230); the cell's side of the fleet (`JoinFleet`, `HostTenant`,
  `DropTenant`, #229); `JoinFleet` carries the universe pointer (`UniversePointer`, `Registry::universe`) when another cell hosts the directory (#232 (multiple cells)).
- `corruption.rs` → `IntegrityFault`, `CorruptionVerdict` → the typed corruption verdict a store surfaces (the journal classifies).
- `registry/event.rs` → `RegistryEvent`, `RegistryRefusal` → what a registry record folded to, or why it changed nothing.
- `registry/control_plane.rs` → `ControlPlaneMode`, `ControlPlane`, `MAX_FAILURES`, `DEFAULT_TARGET` → the control plane's durability (#685 (special tenants are tenants)): `SetControlPlane` sets `auto` (wants `min(target, (storage - 1) / 2)`) or `manual` (refused `ControlPlaneTooWide` past the storage machines), once per request id, checkpointed; a cell with no record follows auto, target 1. `Registry::control_plane` is what `status` shows: mode, wanted, in force, why.
