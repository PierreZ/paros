# paros-roles

One module per paper role, each with its `run_*` loop: `node` (the colocated leader, acceptor and learner), `proxy_leader`, `replica`, `batcher`, `matchmaker` and `frontend`. Written once over `P: ParosProviders`; the same code runs in `parosd` and in `paros-sim`.

A layer of the library (#722 (three products)): it depends only on the layers below it (root *Layout*). Programs use it through the facade, `paros::roles`.

## Map

- `node.rs` → `run_node`, `run_journals`, `RunError`, `BootKind` → the node loop; one journal or a static list (#188); `run_journals` takes `machine: Option<CellMachine>` (a founding member serves its decree answers, #277; an admitted machine its machine contract, #474) and starts or stops each journal placed on the node from the registry's bookings (#474 (journals on admitted machines)); `Reconfigure` and `Retire` name their journal.
- `node/journals.rs` → `JournalStores` (`opened`: a store passed its boot, #208; `node_audit`: the node's own facts, #243), `SingleStore` → per-journal runtime and quarantine (`quarantine_ticks`); a journal a full disk quarantined (`StorageError::Full`, decided `StorageFaultDecision::ReadOnly`) never ends the node and re-opens read-only (`JournalRt::read_only`, #360 (disk full)): `node.rs` drops its `Accept`, catch-up records and handoffs (`read_only_refuses`), keeps it from leading, and makes it writable `read_only_ticks` after the fault (the quarantine counts).
- `node/system.rs` → `ControlPlan`, `ControlFollower` → the control journals' follower: the registry and every hosted tenant's control journal (#189, #210); `run_journals` starts and stops journals from their events. A seed the fold sees registered elsewhere is dialed there (`reseed`), and an admitted machine's node loop moves its seeds and their lanes to a book offered to its cache (`adopt`, #505 (stranded admitted machine)). Each followed journal takes the seeds in its own turn, so no journal is pinned to one seed (#607 (set left on its old machines)).
- `node/{boot,ready,report}.rs` → format-marker check, the `Ready` I/O side in persist-before-send order, boot report.
- `node/transport.rs` → `PeerMailbox`, `LaneOpener`, `peer_address`, `peer_target`, `PeerTarget` → keep-newest lanes per journal, round-robin; a lane's `Dialer` resolves its peer's name before a batch and forgets it after a failed delivery (#257); it dials the peer's machine interface the registry holds, aimed at the resolved address, else the well-known `Deliver`, and falls back to the well-known one after the interface refused a delivery for good (#404).
- `node/{matchmaking,handover,operator}.rs, `paros-observe/src/events.rs` → matchmaker wire (`MatchmakerLinks`: a link to each registered machine is added at its admission, #501 (matchmaker sets off the founders)), set handover (`ReconfigureMatchmakers` names its tenant; its bootstrap paged by `registry_page`, #439), Reconfigure/Retire/Inspect, events.
- `node/edge.rs` → `RpcEdge`, `NodeInbox`, `ReplicaInbox`, `MatchmakerInbox` → the inbound edge, polled as a `select!` arm; it serves and dials with the role's `Transport`.
- `node/scrub.rs` → `serve`, `SCRUB_PAGE`, `SCRUB_PAGE_BYTES` → the acceptor's side of a scrub (#362 (background scrubbing)): the node loop serves `Scrub` (`0x5041_0104`) for a journal it runs, reads one page back from its store (`LogStorage::scrub`), hands each damaged record to `ColocatedNode::repair_record` (written again from the node's own copy, made durable by the settle tail before the answer) and answers each record's ballot and value fingerprint; a failed read answers `unavailable` and quarantines nothing.
- `node/stop.rs` → `Stop`, `Open`, `hand_on`, `refused` → the node loop's clean stop (#560 (clean Ctrl-C shutdown)): once `shutdown` fires the loop serves on, refuses the four data-plane calls `stopping`, answers its held calls and reads, hands every relinquishable leadership on and waits for the successor's beat (a leader that cannot hand off is waited for one election timeout), waits for the cell coordinator's task (`coordinator::spawn` takes the stop token and hands its term on, `hand_on`) and for every flush, then returns; `DriverTunables::shutdown_within` bounds it (`stop_timed_out` names the open step). `frontend.rs` stops the same way, with no leadership.
- `node/reply.rs` → `answer`, `match_answer`, `maybe_duplicate` → the one client-reply seam.
- `batcher.rs` → `run_batcher`, `BatcherSettings`, `BatcherBook` → the batcher (#145 (batchers), §2.4): serves `BatchWrite` (`0x5041_0501`), queues each unfenced write in a `paros_core::Batcher` lane of its journal, sends a flushed lane as one write to the journal's leader (hints followed and stripped, a `paros-batcher-flush` task per batch) and scatters the answer with `Unbatcher`; a merged write refused `too_large` teaches the leader's limits and each write is sent again alone; a merged write with no answer is answered unanswered, never re-sent; a fenced write passes alone with its fence and position. Every machine serves it over the cell's address book (`paros-machine/src/formed.rs`, `paros-machine/src/admitted.rs`), following the cached registry folds; `run_batcher` runs one stand-alone. `CallObserver::merged` tells a harness of each merged write.
- `node/calls.rs` → held `Write`/`SetLeader`/`Truncate`, answered with the verdict their slot folded to (#204); `busy`, `Write` admission (#360 (disk full)): a leader with `admission_rounds` undecided rounds answers `busy`, and `Client::write` sends the same write again.
- `node/log_reads.rs` → `JournalReads`, `ReadLimits` → the public `Read`: quorum-confirmed, served from the fold, its page cut to `max_read_records`/`max_read_bytes` and its tail wait to `min_wait_ms..=max_wait_ms` (#241). Every `Read` waiting in the inbox when the node loop takes one rides the same quorum read (`Input::Read`, one `PreRead` per peer for all of them): each arrived before the row was asked, so one watermark sample serves them all; one quorum read per `Read` let a client's window of pages overflow a peer's keep-newest lane (`peer_queue_capacity`) and expire unserved (replay-main 18315968079077685493 on 86ca15c). BUGGIFY: the first read goes alone.
- `node/metered.rs` → `Meter`, `journal_names` → the node loop counts each `Write`, `Read`, `SetLeader` and `Truncate` where it takes it, and times and counts the answer by outcome (`write_answer`, `read_answer`, `set_leader_answer`, `truncate_answer`) through `ReplySender::observed` (`paros-net/src/inbound.rs`); `Shared::settle` records the settle time and the slots.
- `matchmaker.rs` (its store: `paros-storage/src/matchmaker.rs` → `run_matchmaker`, `HostedSet`, `Host`, `SetOpener`, `MatchmakerStorage`, `MemMatchmakerStorage`, `Registrations`, `matchmaker_storage_contract_suite` → one matchmaker set per tenant, one registry per journal inside it (#190); a request names its tenant, its journal and the matchmaker it addresses (a misaddressed one is dropped); `Host` is the loop, fail-stop for a matchmaker process, closing only the set on a machine; the driver reports what a commit has in flight (`Audit::matchmaker_in_flight`).
- `proxy_leader.rs` → `run_proxy`, `ProxyConfig`, `ProxyJournal` → Phase-2 subset, nothing durable (#142); one `ProxyLeader` per journal, demuxed by `JournalIdentifier`, each journal's facts to its own audit port (#193).
- `replica.rs` → `run_replica` → learner subset over a `LogStorage` per journal, opened through `JournalStores`; one `ReplicaNode` per journal, serves `Read` per journal (#144, #193); a storage fault on any journal restarts the replica.
- `node/book.rs` → `PeerBook` → a founding member folds its own copy of the cell control journal after each tick (each peer's address and machine interface, #404; a fresh interface may be held back one fold, and a moved address for `MOVE_HOLD_TICKS`, each a BUGGIFY decision), from its cached registry fold's addresses on (no lane moves below the cache's position, and each later book is offered to the cache, #211); a peer the address book moved is dialed at its new address from its lane's next batch on (`PeerMailbox::readdress`, #349).
- `frontend.rs` → `run_frontend`, `FrontendSettings` → the frontend (#192 (the frontend), §3.5): authorize in names, resolve, forward; one task per call, its BUGGIFY draws (a cold cache, a stale resolution answered as unknown, a stray first server) made on the loop and carried in (`Draws`); `Audit::frontend_resolved` reports each resolution, and `Audit::frontend_unknown` each name its fresh read found no live journal for (#451).
- `frontend/routes.rs` → `Routes` → the frontend's caches (it serves only its own cell's tenants: another cell's is unknown, #232 (multiple cells)): the cell (learned with `majority_cell` from its founding members, each called through the machine interface it gave, #404; forgotten when a server refuses a stale one, `stale_cell`, unless a BUGGIFY decision of the call keeps it), the universe directory (kept for static stability while it is unreadable) and its root keys (`keys`: the keys last read rule while it is unreadable; a token refused `invalid_token` reads them again once, #245 (Biscuit tokens)), each tenant's names, a leader hint per journal.
- `frontend/forward.rs` → `Forwarded`, `forward` → one call to the machines: redirects followed and stripped, the next server on an unknown journal or an attempt refused unrun; a write that may have run with no answer is `FrontendVerdict::Unanswered`, never sent again; a read moves on from any failure.
- `node/grid.rs` → where a round goes on a grid: a stuck round moved to another column (#533), the Phase 2 column (#141), the fast row and column around slow members (#361).
- `node/shared.rs` → `NodeLoop`, `Shared` → the node loop's handles: the fixed context of every arm's settle tail, and what every journal's steps share.

## Tests & gates

- `cargo nextest run -p paros-roles` — the node loop's tests, inline tests.
- Faults are inline here (root *Simulation rules*, #294): a driver decision is a `buggify_with_prob!` / `buggify_pick!` at its line, drawn only on the node loop; a durability moment is `hint!("label").await` with a `reachable!` on `Strike::Killed`. Never a hook trait, a `Seam` or a sim wrapper.
- Spans are non-optional (`#[tracing::instrument(skip_all, fields(..))]`).
