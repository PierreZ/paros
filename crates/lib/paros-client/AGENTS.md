# paros-client

`paros::client`, the library client of a cell: the writer, reader, pipeline and multi-writer policies, and the control-plane sessions (cell, fleet, journals, views, load, capacity, resolve). Provider-generic like the roles.

A layer of the library (#722 (three products)): it depends only on the layers below it (root *Layout*). Programs use it through the facade, `paros::client`.

## Map

- `lib.rs` → `Client` (`elsewhere`: the same runtime over another cell's machines, #232 (multiple cells)), `ClientTunables`, `Retarget`, `LeaderHint` → policy loops: `write`, `resolve`, `read_any`, `journal_state`, `claim`, `set_leader`, `truncate`, `reconfigure*`, `inspect`, `retire`; `*_attempt` one-shot calls.
- `outcome.rs` → `WriteOutcome`, `ReadOutcome`, … → every reply judged once; a frontend's verdict first (`Denied(Denial)`, or `Unanswered` as `Ambiguous`, #192 (the frontend)).
- `writer.rs` → `Writer`, `leader_uuid` (a uuid per term derived from the caller's random seed, #241; `with_uuid` for an operator-named one; `truncate` carries the leader's fence, #228; `stale_entry` and `stale_truncate_request` are the explicit misbehaviours) · `reader.rs` → `Reader`, `ReaderOutcome::Gap`.
- `pipeline.rs` → `Pipeline`, `Ticket`, `Pipelined` → several writes in flight on one single-writer journal (#597 (several writes in flight per journal)): one `Writer` shared behind a lock, `open` gives consecutive positions, `send` sends one through `Writer::write_entry`; a write refused early (its own uuid, a tail below it) waits for the writes in front of it, then is sent again unchanged, or returns its refusal when one of them failed; a failure stops new writes until the flight drains; a won claim opens at its view's tail; writes sent together merge into one write at the first one's position (#709 (merge fenced writes): a send waits one executor turn, then the first ready write carries the ready writes after it, up to `MERGE_RECORDS`/`MERGE_BYTES`; a `TooLarge` merged write comes apart and each goes alone). `Lanes` is the pure state `tests.rs` pins.
- `multi.rs` → `append_entry`, `append_request`, `open_truncate_request` → the unfenced calls of a multi-writer journal (#241): the unset leader uuid and `seq` 0; the library never re-sends one on its own.
- `observer.rs` → `CallObserver` (every attempt, and every `resolve` settlement: `resolving`/`resolved`, #444), `NoObserver` · `tests.rs` → the pure parts pinned.
- `bootstrap.rs` → `cell_init`, `InitOutcome`, `discover`, `majority_cell`, `CellServer` (the cell a majority of a list serve, #216, each server with the machine interface its `Inspect` gave, #404), `control_journals`, `control_journals_of`, `cell_members`, `identify`, `admit` → `parosctl init`'s calls: `cell_init(providers, rpc, target, members, patience)` sends `CellInit` to one founding member (#277); server ids and the control journals learned from a node-only `Inspect` (#196, §3.8, #243).
- `election.rs`, `election/fold.rs` → `Election`, `ElectionTunables`, `Step`, `ElectionFold`, `ElectionRecord`, `Candidate`, `Leader`, `hand_off`, `read_election` → the election library over a multi-writer journal (#240): campaign, renew, watch, resign; a lease on the watcher's own clock as a liveness hint only; the leader truncates to its own latest renewal; the caller hands in the jitter and the seed.
- `cell.rs` → `CellSession` (`with_leader`: an elected coordinator's term uuid, #240; `drain`: `DrainNode` for a registered machine, #474; `remove`: `RetireNode` for a drained machine with no slot, and `maintenance`: a maintenance window over a machine or a zone, #359; after each write that lands, the session checkpoints and truncates the cell control journal when its policy finds it due, as `FleetSession` does, #650 (registry fold oracles on the machines)) → `cell add-machine` (#216) as an idempotent state machine: `Identify` the machine, `RegisterNode` in the cell control journal unless held, then `Admit` with the cell and the machines the session knows; reuses the fleet operations' `Step`, `Stage`, `Run`.
- `initialize.rs` → `initialize`, `InitRun`, `Initialized`, `InitRefusal`, `Unreachable`, `InitParams` → `init` whole (`cell init` at the first listed member still idle, retrying `member_unreachable` and `contended` within its patience; a wait for the elected cell coordinator, #240; the fleet steps, which claim nothing on the cell control journal, #513 (fleet Init duel); no wait for the registry: the coordinator registers the founding members and books the cell's footprints, #476 (tenant footprint); none of the fleet steps on an idle run, `InitParams::idle`, #232 (multiple cells)) as one resumable operation over the founding members, typed; `parosctl init` prints it and the simulation runs it (#246).
- `views.rs` → `ViewOutcome`, `request`, `ask` → a view sent to the servers of one cell in turn, until one answers; `unavailable` passes it on.
- `load.rs` → `LoadOutcome`, `ask_all` → `Load` to every machine of a cell view at once, each within a timeout; `Silent` is `no metrics` (#424).
- `capacity.rs` → `CapacityRequest`, `Wanted`, `CapacityAnswer`, `request` → the capacity request RPC's caller (#476 (tenant footprint)): one idempotency id re-sent to the coordinator found from the election journal until decided.
- `resolve.rs` → `resolve`, `Resolution`, `Resolved` (`servers`: a client's servers through each machine's interface, #404; `batchers` and `batcher_servers`: the tenant's booked batchers, #145 (batchers); `frontends`: the machines that hold its frontend slots, #723 (frontend as a parosd role)), `from_wire` → `Resolve` at the entry endpoint (#216): each address in turn, a machine that does not answer or answers `unavailable` passed over; an `other_cell` answer with the tenant cell's endpoint is asked there once more (#232 (multiple cells)); `parosctl resolve <tenant>` prints it.
- `names.rs` → `resolve`, `resolve_tenant`, `resolve_journal`, `JournalNames` → name resolution (#239, §3.5): the tenant name through the universe directory (only a `READY` `users` tenant; an internal one never), then the journal name through the tenant's control journal (`Directory`, only a live journal); `JournalNames` caches each resolution and drops it when a call refuses its journal as unknown (`stale`).
- `universe.rs` → `JoinRequest`, `JoinAnswer`, `send`, `join` → `universe add-cell`'s cell step (#232 (multiple cells)): `JoinUniverse` sent to the idle cell's coordinator, found from its election journal, until an answer decides it.
- `fleet.rs` → `FleetSession`, `Step`, `Stage`, `FleetRefusal`, `CellJoin`, `read_directory` → `universe add-cell` and `remove-cell` (`add_cell`, `remove_cell`: an idle cell added with its entry endpoint, joined by its coordinator, marked `READY`; an empty cell marked `REMOVING`, then removed and tombstoned) and `tenant create` in a chosen cell (`with_cell`; another cell's registry read through `Client::elsewhere`, #232 (multiple cells)); `init`'s fleet
  steps and tenant create/remove as idempotent state machines over the fleet tenant and the cell control
  journal, one write per step, resumed from what the journals hold (#229); the session writes only the
  fleet tenant and reads the cell control journal (`read_cell`): `init` waits for the coordinator's
  `JoinFleet` (`Interrupted::NotJoined`, #513 (fleet Init duel)), a creation for its footprint and
  its `HostTenant` (`Interrupted::NotHosted`; the cell refuses no footprint while a founder is
  unregistered and not marked down, so the creation waits; #614 (a tenant waits for a wiped founder)), a refused footprint marking the tenant `ERROR`
  (`NoFootprint`, #476 (tenant footprint)), and a removal for its `DropTenant`
  (`Interrupted::NotDropped`, #225). A run's patience counts from its last written step (#605 (init pending in the recovery tail)).
- `journals.rs` → `JournalRequest`, `JournalAnswer`, `Coordinator`, `request`, `coordinator`, `list` → a tenant's journals (#210), and `JournalOp::Configure`, FDB's `configure` (#214 (tenant modes)); a create with no mode takes the tenant's default: the coordinator found from the election journal's published interface and term group (#404), one request id re-sent until decided; `list` folds the control journal.
