# paros-machine

One machine's lifecycle: `run_machine` (format, wait for a cell, serve it), what an idle `parosd` does until `cell init` forms its cell, and `inspect`. The top layer below the facade.

A layer of the library (#722 (three products)): it depends only on the layers below it (root *Layout*). Programs use it through the facade, `paros::machine`.

## Map

- `lifecycle.rs` → `run_machine`, `MachineSettings`, `MachineAddresses`, `MachineError` → the whole machine lifecycle `parosd` and the simulation run (#246): format (mint `node_id`), the amnesia and class checks, wait (an acceptor of any `cell init` that lists it), serve the plan and keep answering the decree; it binds the listen address and advertises the other (`MachineAddresses`, #257: a wildcard listen address with no advertised one is refused), and dials through the caller's `Names`; the disk is a bare `ProviderDisk` over the caller's provider and the audit port is the caller's (`AuditScope`, #294); a late boot is an inline `buggify_range!`; a failed record read or write is `MachineError::Storage`, a restart, never a refusal.
- `pin.rs` → `AdminPin` → the bootstrap pin (#245 (Biscuit tokens)): an idle machine checks an `admin` token on `CellInit`, `PrepareCell`, `FormCell` and `Admit` through an `Authz` at its epoch plus the provider's time; open by default; a refusal answers `invalid_token`, `expired` or `forbidden`.
- `wait.rs` → `wait_for_cell`, `CellLedger` → the idle machine (#196, #216, #277): `Identify`; `PrepareCell` and `FormCell` as an acceptor of the cell decree (accepting is forming: `format`, then the vote; a `hint!` after the durable promise and one between the format and the vote, #246, #294); `CellInit` as its proposer over the founding members, every one an acceptor: all answer Phase 1, a majority chooses (#246: a wiped member stays a dead member of the plan; `cell_lost` once a majority is wiped) (adopt a reported plan, else draw one; form the others, then itself; a vote for another list's plan is another cell's, never adopted, #216).
- `admitted.rs` → `AdmittedMachine` → a machine `cell add-machine` admitted (#216): serves `Identify` (with its newest registry fold's `registry_position`, #505 (stranded admitted machine)) and a node-only `Inspect` with its cell, acks `Admit` into its own cell as `in_cell`, so `cell add-machine` reports no `Admit` stage it did not record (an admission that landed between its `Identify` and its `Admit`) (adopting its book into the cache when it is taken past its own fold and names other machines, #505), refuses the cell decree (`in_cell`, so `cell init` is `cell_exists`); it runs the node loop and serves the journals placed on it, following the control journals through the founding members (#474). `Admission` (in `paros-model/src/machine.rs`) is what `Admit` carries and the record keeps (`admitted`, `control`, `fleet`, `peer`, `founder` lines).
- `follow.rs` → an admitted machine folds the registry through the machines it knows each renewal period and offers each new book to its cache (#211); a book offered past its own position (an adopted `Admit`, #505 (stranded admitted machine)) is the book its next read dials.
- `resolve.rs` → `Resolver` → `Resolve` (#216, §3.5): every machine of a cell, founding or admitted, answers "which references serve tenant T" in a task of its own (another cell's tenant `other_cell`, with that cell's entry endpoint, #232 (multiple cells)), from folds of the universe directory (read at the registry's universe pointer when another cell hosts it) (the tenant's id, control journal and cell, with `universe_id` and the universe's and cells' names, #239; `tenant_in` judges the name) and the registry (the cell's machines, `cell_book`), kept between requests and read through the cell's machines like a client, each machine answered with the interface the registry holds (#404); each answer bounded by `DriverTunables::resolve_answer_within`, and an answer cut short keeps what its folds read (#457 (hard-coded tunables): a reset to position 0 never answered again once a fold outlasted the bound); one BUGGIFY decision drawn at spawn answers every request from fresh folds.
- `register.rs` → the machine-to-coordinator request path (#349): on every start a formed or admitted machine reads the election journal for the coordinator's published interface (`client::journals::Coordinator`: the address and the term group's reference, #404) and sends it `Register` with the address it advertises now and its machine interface, again each renewal period until the registry holds it; it reads the election from its peers, never its own node while it has peers, from a first peer a BUGGIFY decision draws, and a round that finds no coordinator starts from the next peer (#479 (renamed founder not registered)). Its receiver ends a moved founding member's hold: the node loop beats no journal (#390) and the member does not campaign for the cell coordinator (#506 (renamed founder not registered)) until then.
- `formed.rs` → `FormedCell` → a formed machine answers the decree (`PrepareCell`, `FormCell`, `Identify`) from its record while it serves its cell (#277), and teaches it (`Teacher`, the decree's learner catch-up): each election renewal period it `Identify`s the other members of its plan and re-sends its vote as `FormCell`, with the operator's token that formed it (`FormedCell::token`, `FormationToken`: in memory only, never in the record; none after a restart, so no teaching), to one that answers idle, until each member formed, answered as another machine, refused the token, or moved to another address in the cell's address book (the cache's offered books).
- `matchmakers.rs` → `SetBookings` → a storage machine's matchmaker host (#190): the shipped matchmaker loop in a task on the node's edge (`JournalStores::host_on_edge`), every tenant's set born on the founding members (`CellPlan::matchmakers`), a set provisioned at its first request and recorded in the disk's `sets` file (the commit point; a `hint!` between the format and the record); a machine that is not a founding member provisions only a set the registry books on it (`JournalStores::book_sets`, #501 (matchmaker sets off the founders)), and a released set stays open, frozen, for the successor chain.
- `disk.rs` → `ProviderDisk` → the record's atomic rewrite (staged, synced, renamed, every directory on the way synced), the amnesia probe and the formation's stores over any `StorageProvider`: `parosd` and the simulation both hand it to `run_machine` bare (#246, #294).
- `stores.rs` → `AuditScope`, `MachineStores` → a formed machine's `JournalStorage` per plan journal, an existing member's (ordered); a journal a tenant created opens under the store durability its create recorded (#599 (durability mode per journal)) and is provisioned at its first open (`provision_store`, then the record's `created` line, the commit point), then boots as an existing member (#210).
- `views.rs` → every founding member serves `View` (#399): folds the registry and the universe directory to their tails (a lagging member answers once from its fold, an inline `buggify_with_prob!`), reads the election journal and the tenant control journals, then answers through `crate::view`, the status words shown through its own `Hysteresis` (`status_hold`, #191 (status)); an unreadable universe directory still answers from the registry (static stability).
- `load.rs` → `LoadBoard`, `Window`, `answer`, `with_usage`, `usage_to_wire`, `usage_from_wire` → a machine samples its own counters every `load_interval` in one task per run, keeps its last full window, and every phase serves `Load` from it (#424); one BUGGIFY decision, drawn in `run_machine`, skips the first window. Each window also goes to the metrics, and `LoadAck` carries `metered` and the usage per journal (#366 (metrics)).
- `inspect.rs`, `inspect/{scratch,names}.rs` → `inspect`, `DiskImage`, `JournalImage`, `StoreImage`, `SetImage`, `SetStoreImage`, `names` → offline store inspection (#365 (offline store inspection)): a machine's disk read without `parosd` and never written: each store's files copied to a scratch directory on the caller's provider (`Scratch`), the copy opened with the shipped stores' boot scan and deleted after; `names` folds this disk's copies of the registry, universe directory, election journal and hosted tenants' control journals over each store's accepted prefix (writes judged by `JournalState::apply`, stopping at the first slot it lacks) and answers `view::cell_view` from them. `inspect/tests.rs` reads stores the shipped code wrote on `SimStorageProvider` and checks the source bytes are unchanged. `parosctl store inspect` prints it.
- `cell_init.rs` → `cell init`'s proposer (#277): the single-decree Paxos on the cell plan over the listed machines, through `paros-core`'s `Decree`.
