# paros-sim

The DST harness on top of `paros`: moonpool `Process` adapters, the deployment/role map, the
fault world, the one client workload and the audit. Stack: `paros-core` ←
`paros` ← **`paros-sim`** ← `paros-sim-runner`. Correctness lives here (audit + workload
`check()`), never in a trace scan. Doctrine: root *Simulation rules*, *Turbulence layers*,
*Audit, correctness, assertions, spans*.

## Map

- `lib.rs` → `chain_builder`, `chaos_surfaces()`, the campaign constants, the entry points.
- `roles.rs` → `Deployment`, `Role`, group names, `joiner_node_id`, `replica_node_id` → the per-seed role map.
- `shape.rs` → `NodeShape`, `QuorumPolicy`, `JournalPlan` → every per-seed and per-node draw (below).
- `process/mod.rs` → `NodeProcess::chaotic`, `MatchmakerProcess`, `ProxyProcess`, `ReplicaProcess`, `dispatch`, `arm_role` → one process group per role (#416): `process/acceptor.rs` (`run_acceptor`, one `Seat` per journal, the system journals' rig), `process/stores.rs` (`SimStores`, provisioning), `process/matchmaker.rs`, `process/proxy.rs`, `process/replica.rs`, `process/joiner.rs` (`JoinerProcess`, `IdleProcess`), `process/contract.rs` (`ContractSuiteWorkload`); `journal_config` and `main_config` → the configuration every role derives for each journal of the run: the proxy leaders and the replica tier serve every journal (#193), and a node counts `proxy_count - NodeShape::proxy_count_lag` proxies (default 0, extreme 1–2, floor 0: a rolling change of the count, liveness only).
- `machine.rs` → `MachineProcess`, `MachineBoard` → the machines (#246): the shipped `paros::machine::run_machine` on a bare `ProviderDisk` over the simulated disk (no wrapper, #294), from an empty disk, formed by the workload's `init` (`cell init`'s decree over the layout's founding members, #277); stores ordered (a cut mid-commit is torn or whole), outside the injector, but a created journal's, which stores in the mode its create recorded: on a `shape::batched_journals` seed three creates in four are `Batched` (#599 (durability mode per journal)), cut under the machines' budget (`world/cut.rs`); oracles: no cell forms without `init`, every formation names the one cell, only a founding member forms and over exactly the founders, every admission names a cell `init` formed and an admitted machine holds no vote and no promise (#216), the other cell an operator founds is a plan over its one machine and never the run's (#216), a durable cached registry fold only moves forward and a boot reads only a cache its machine wrote (#211) (the lifecycle reports through the audit port, `NodeAudit::on_machines`), a failed record write restarts the machine (the one loop: `parosd`'s supervisor); its faults are the lifecycle's own `hint!`s, struck by the machine group's attrition, which also draws moonpool's `CrashAndWipe` (`MACHINE_WIPE_WEIGHT`), rolling (decided on 2026-10-18, moonpool #344 (rolling wipes)): a wipe budget of one unhealed wipe, healed by `machine/heal.rs` once no registry the machines fold books a slot on the old id (a founder never heals), every other drawn wipe a plain crash meanwhile; a wiped machine is a new one, recognized at its boot on an empty disk; a vote that names the old one keeps it as a dead member, and the cell is lost only when a majority of the plan's members are wiped (`cell_lost`, the Paxos limit; the control-plane liveness is excused only then).
- `machine.rs` (#366 (metrics)) → `machine_metrics`, `check_metrics` → every machine records into the `paros::metrics::Metrics` the board keeps for its IP (`MachineBoard::metrics`), so a reboot finds its counters; on a seed that draws `shape::unmetered` every machine runs with `Metrics::off`, judged by the same oracles (metrics never change an outcome). The board folds `Audit::call_received` and `call_answered` (`NodeAudit` forwards them) into `MachineBoard::metered`, and client 0's `check()` asserts that the machines' counters (calls and answers per call, bytes) equal that fold, and are zero on an unmetered seed; gate "metrics: the machines count calls, written and read bytes".
- `machine.rs` (#257) → `names`, `process_ip`, `boot_listen` → the machines' name table (moonpool's `ScriptedResolver`, `machine-<rank>.paros`): on a seed whose layout is `named`, each machine advertises its name, and a rebooted machine comes back at a new IP behind it (`MachineLayout::move_pct`, a knob: default 0, extreme 20–80%, floor 0; the new IP is an alias its name points to); the board maps an advertised address to the process IP a kill strikes. Moonpool's network faults strike by process IP, so a moved machine's alias IP is outside them. A cell machine's reboot may also come back under a new name at a new IP (`MachineLayout::rename_pct`, #349, a knob: default 0, extreme 20–60%, floor 0): `machine-<rank>-<n>.paros`; the old name keeps the old IP, where nobody listens. The machines resolve through one table and the workload's clients through another (`names`), where the rank's name follows its machine, as an operator updates its own entry. A rename never takes the cell's majority: no founding member wiped, no other founding member renamed, and not a cell of two (`may_rename`); a founding member is renamed only once every renamed machine outside the founders is registered at its new name, as its own cached registry fold shows (`renamed_outside_registered`, #501 (matchmaker sets off the founders)); a later wipe counts a renamed member as lost (`cell_lost`). The board knows a machine by its rank's address. After chaos the final check judges that the registry holds every renamed founding member and every renamed admitted machine at its new name (`FleetOps::renamed_registered`).
- `frontend.rs` → `FrontendProcess`, `Presented`, `token`, `frontend_addrs` → the frontends (#192 (the frontend)): the shipped `run_frontend` with `BiscuitAuthz` in front of the founding members (`FRONTEND_POOL_RANGE`, 0–2, crashed by their group's attrition); root keys drawn per seed (#245 (Biscuit tokens): the signing key, which `init` writes in the universe entry and every frontend pins; a key an operator rotates in through the universe entry on a `TENANT` BUGGIFY location, `fleet/keys.rs`, with a spare key added and removed; a key on no list); on half the seeds every machine pins the signing key (`machine_pin`), and `init` and `ADMIT` present an `admin` token, or on their own locations a tenant's, which must be refused; the clock is a fixed epoch plus the simulated time, each frontend's skewed by up to `MAX_SKEW` (2 s) either way (a knob per boot, #450); oracles: each resolution is the journal the tenant board records at its position (`Audit::frontend_resolved`), and a name answered unknown is one the board records no live journal for at the position read (`Audit::frontend_unknown`, #451). Every `CREATE_JOURNAL` and `DELETE_JOURNAL` step on a seed with frontends calls a journal of its tenant through a frontend (`fleet/journals.rs`, `through_frontend`): a read or a claim and a write by name, with the tenant's token, one derived from it (read-only, its one journal, #400), the rotated key's (served only once an operator tried to add the key, and may be `invalid_token` until the frontend read it), an `admin` token, a sealed one, one derived to its own tenant or to the journal class (a tag served, a data call denied), a short-lived one whose expiry lies within 6 s of its minting either way (served only before its expiry and refused `expired` only past it, both within `MAX_SKEW`), or one that must be denied for its cause and never served (another tenant's, expired, an unknown key, garbage, a tenant token on an internal journal by ids, a read-only token on a write, one derived to another journal or tenant or with an expiry past, one past `MAX_BLOCKS` blocks, #450). A write the token must deny carries a payload and a claim uuid the tenant board holds, and its write is sent after its denied claim anyway: no node applies either ("frontend: a denied call never changes a journal", #450). On a coin, a token whose rights hold every call runs the created-journal data plane through the frontend by name (`fleet/created.rs`, #451). A node never denies a call (`rpc.rs`).
- `lifecycle.rs` → `ScriptedLifecycle` → the `fault_factory` injector (the chain client's operator crashes and reboots, #173); `restart_at` schedules a restart the injector runs at a deadline, so a hold ends even when its client is blocked (the static-stability hold, #426 (static-stability hold)).
- `tls.rs` → `seed_tls`, `serving`, `dialing` → TLS on some seeds (decided on 2026-10-11, PR #509 (mutual TLS)): a dice rolled by the first process that asks turns TLS on for every runtime of the seed (half the seeds), with one `ClientCertificates` mode per seed and one authority from seeded keys; every role (acceptor, matchmaker, proxy, replica, joiner, machine as `machine`; frontend as `frontend`) issues a fresh leaf at each boot with `paros::tls::leaf`, a flawed one (the issuer's BUGGIFY site) reissued; a client presents an admin leaf under `required`, on a coin otherwise. The clock is the frontend's `EPOCH` plus the simulated time.

## Harness shape

- **Main campaign**: process groups `paros-node` (acceptors, 3–6), `paros-matchmaker` (0–5),
  `paros-proxy` (0–3, `ProxyId(rank)`), `paros-replica` (0–2, `NodeId(1000 + rank)`, a quiet
  journal store outside the copy budget), `paros-joiner` (0–2, `NodeId(100 + rank)`, idle without system
  journals), `paros-frontend` (0–2, #192 (the frontend)), `paros-machine` (1–4, a minted `node_id`; `shape::machine_layout` draws the founding
  members, each machine's class, capacity, zone and rack). Attrition per group (`AttritionVictims::group`); joiners are no victim. 1–3
  `ChainWorkload` clients. Zero matchmakers = the plain Multi-Paxos deployment.
- **Bootstrap**: `bootstrap_ranks` — the whole pool, or on a matchmaker seed a subset of at least
  `MIN_BOOTSTRAP` leaving *spares* a `Reconfigure` pulls in.
- **One campaign** (#263): the scripted CTRL corpus is folded in. Shapes are provoked through
  BUGGIFY and swarm, never scripted: the correlated outage and its planned losses
  (`world/outage.rs`), aimed rot, `withhold_gc` (a removed straggler stays worth waiting for),
  an owner's member-removing reconfiguration right after its claim (`ChainConfig::reconfigure_after_claim`),
  each recognized by the audit from the ledger and judged by the same oracles
  (`audit/losses.rs`).

- Each client is an **owner** or a **reader** for the run (knob; each journal's first client
  owns). Every library writer, session and checkpointer a client starts draws a fresh leader seed
  (`LeaderSeeds`, #241), so a well-behaved client never reinstates a uuid. Owners claim before writing — the opening claim re-asked within `claim_patience_ms`
  while the cluster leaves it unresolved — and re-claim when superseded.
- Every client folds its journal into `ChainState` and reports each step
  (`AuditWorld::fold_applied`); truncations are clamped below the lowest folding cursor.
- Races (#205, each a BUGGIFY location): a claim racing its own burst, a write with
  `ack_race_timeout_ms` below its ack retried across a re-claim, a `READ` from a lagging cursor

## Boards

- **Journal board** (`audit/journals.rs`): every slot of journal `j` applies only an identity
  appended to `j` (a write sent under another tenant's fence only as a refusal, #247); a
  quarantined journal sends nothing; a sibling keeps committing while one is held; a node keeps
  serving the rest while one is quarantined; a tenant journal commits while the control
  journals' seed is held down (static stability, #247). The hold is more likely under a grid, where it freezes one column (#426 (static-stability hold)).
- **System board** (`audit/system.rs`): one booking model per registry journal (#650): the harness registry on the acceptors, and every cell control journal the machines fold (their ports report folds, checkpoints, started journals, the record and the cache, `Plane::Machine`, judged by the class and capacity `shape::machine_layout` drew; the joiner gates stay the harness registry's); a machine's durable cached registry fold holds, at its position, the registry's address for every machine the registry holds there and no retired one, judged once the model reaches that position; gate "registry: a machine's fold crosses a granted booking at a checkpoint"; every node folds the registry alike per LSN; a checkpoint a node (or a client) meets
  with the whole prefix folded is that prefix's state (#230); a `stateless` joiner never serves
  a journal, a booking takes a slot of its node's class and never past its capacity, and a
  booking id is booked at most once, across checkpoints (#211, on the registry's events in LSN
  order; the model crosses a truncation at the checkpoint a restoring node meets, resuming its
  bookings and spent ids, and equals every checkpoint it reaches, #247); no genesis node's message waits on the registry fold; every live node's
  registry fold reaches the tail after chaos; gates for
  joiners learning before admission, refused-then-accepted joiner messages, a re-registration,
  and a fold restarting from a checkpoint once one truncated.
- **Tenant board** (`audit/tenants.rs`, #210): every machine folds a tenant control journal alike
  per LSN; a created journal takes a set id never used before, inside its own tenant (`IdTaken`
  only for an id used before); a request folds to one outcome, and a repeat reads it back; a
  delete names a journal created before, and a journal is deleted once; no append acked, and no
  `SetLeader` or `Truncate` answered, after its tombstone; a machine starts only a tenant's
  control journal or a journal the tenant created; a quarantined journal answers no call; no node
  applies a write or a claim a frontend had to deny (#449, #450); the writer mode a
  created journal runs in (`writer_mode`); gates for `name_taken`, an `IdTaken` redraw and a
  retried request.

## Local rules

- moonpool macros only; never plain `assert!`; never reword a message. Budget: 2048 slots
  (moonpool `MAX_ASSERTION_SLOTS`), 256 buckets; no slot, ballot, id, seed or hash as identity.
- No seed constants, seed lists or seed-replay tests (root *Simulation rules*).
- **No new fault wrapper here** (root *Simulation rules*, #294). This crate never decides a
  fault by wrapping shipped code: no new `Ledgered*` store, `Sim*` disk or stores, timer race
  around a commit (the deleted `PowerCut`), hook trait (the deleted `BuggifyHooks`), `crash_self` call on a code path, or workload that stops the
  library's own loop to fake a crash. Put an inline `buggify!` or a `hint!` in `paros` instead,
  and keep here only what observes (`Audit`, oracles), the environment's injectors (outages,
  disk rot) and an operator's explicit misbehaviour. `LedgeredJournal` and `LedgeredRegistry`
  are the old pattern, migrating away (`SimDisk`, `SimMachineStores`, `PowerCut` and
  `BuggifyHooks` are gone); extend none of them. A per-seed scenario decides the driver's named
  locations with `moonpool_sim::set_activation` in `shape.rs`, never with a wrapper.
- A wiped identity stays down because the **library** refuses it (#147, #183): the ledger parks
  it for the budget and composer only, and `StorageWorld::provisioned` is the `BootKind` claim.
- Operators coordinate an acceptor's retirement through `StorageWorld::retire`, and a joiner's through the registry (`SystemOps::hold_joiners`, #477 (retire coordination moves into the control journals)). Spans are non-optional.
