# paros-wasm-demo

A single, growing WASM demo that *teaches* the Paxos family in the browser. The
Rust core does the work — `runSeed(seed)` runs the whole deterministic simulation
in the browser and returns a `RunResult` as JSON; the front-end only *reads that
data* and draws it. Same seed ⇒ same run, here and in CI.

It is built as **one shell + pluggable renderers**: the shell owns all shared
chrome (flavour tabs, transport, narration, digest chips, oracle badge, responsive
SVG stage, keyboard, the glowing message particle); a *mode* is a renderer object.
Adding a mode is a drop-in — the shell never changes.

```
web/
  index.html            DOM skeleton + design-token CSS + <script src=app/main.js>
  app/
    main.js             entry: init wasm, parse URL params, boot the shell
    shell.js            the instrument chrome (transport, layout, particle anim, inspector)
    registry.js         the MODES map (single / multi / read / log / crash / disk / corrupt / ctrl)
    adapter.js          RunResult → derivations + node snapshots (the contract boundary)
    tokens.js           the design system (palette, phase colours, spacing, type)
    svg.js              SVG helpers + vector badge glyphs
    modes/
      single.js         single-decree renderer
      multi.js          multi-paxos renderer
      read.js           linearizable-read renderer (#43: the commit barrier)
      log.js            catch-up / compaction / snapshot renderer (#31)
      crash.js          crash & recovery renderer (still timeline)
      timeline.js       shared lane scaffolding for the storage timelines
      disk.js           fail-stop disk-fault renderer (#32, still timeline)
      corrupt.js        corruption-detection renderer (#33, still timeline)
      ctrl.js           CTRL recover-or-wait renderer (#34, still timeline)
    fonts/              IBM Plex woff2 (generated by build-wasm-demo.sh; gitignored)
```

Build & stage into the book with `scripts/build-wasm-demo.sh` (also run by
`.github/workflows/pages.yml` before `mdbook build`). The `wasm-bindgen` crate pin
in `Cargo.toml` must match the flake's `wasm-bindgen-cli`.

## Query-param contract (preserved)

| Param | Effect |
| --- | --- |
| `?embed` | Hide page chrome; report height to the parent via a `paros-resize` postMessage (the book's `iframe-autosize.js` listens for it). |
| `?mode=` | `single` (default) · `multi` · `read` · `log` · `crash` · `disk` · `corrupt` · `ctrl`. Chosen client-side over one universal payload. |
| `?seed=<n>` | The seed to run (defaults to the mode's first curated lesson). |
| `?still=<k>` | Render one frozen deterministic frame (for screenshots); no autoplay. `k` maps to the frame containing protocol leg `k`. |
| `?dump` | Dump the raw `RunResult` JSON into `#raw` and stop. |

## Adding a mode

Write a renderer object and add it to `app/registry.js` — that is the whole change.
The shell reads this interface:

```js
{
  id: 'crash', label: 'crash & recovery',
  transport: 'step' | 'still',                 // 'still' hides the step controls
  seeds: [{ value, caption }],                 // curated lessons
  seedCaption(seed): string,                   // caption for the narration card
  stageSize(mobile): { w, h, scrollW? },       // SVG viewBox for the breakpoint
  frames(run): Frame[],                        // ordered teaching steps from events
  render(frame, ctx): { tick(t)? },            // draw the SVG stage; optional particle updater
  narrate(frame): { phase, color?, title?, lines[] },
  digest(run): [{ label, value }],             // summary chips
  progress(run, frame): { type:'track'|'committed'|'none', ... },
  inspect(frame, selection): [{ group?, k, v, swatch? }] & { title },
}
```

`ctx` passed to `render` is `{ stage, dims:{w,h,mobile}, run, selection, reduced,
onSelect(id) }`. Draw into `ctx.stage` (an already-cleared `<g>`); make nodes call
`ctx.onSelect(id)` to open the inspector; return `{ tick(t) }` to animate the
message particle along its link as `t` goes 0→1 (the shell drives it, and honours
`prefers-reduced-motion` by jumping to `t=1`).

A `Frame` is whatever your `frames(run)` produces; the shell only relies on
`frame.timeMs` (for `?still` mapping) and `frame.index`. Stash any per-frame
derived state on the frame object (the v1 renderers stash `__snap = nodesAt(run,
t)` so `narrate`/`inspect` can read node state without re-deriving).

**Because a `RunResult` is mode-agnostic, switching flavour swaps the renderer and
re-derives frames from the same run — no wasm re-run.** That is why the crash
renderer slotting in required zero shell edits, and why the future animated-crash
mode (frames on the same time axis, durable-vs-volatile split, recovery badge)
already fits.

## Step-0 contract map (RunResult → what the UI derives)

The whole contract is the flat `RunResult` in `crates/paros-sim/src/oracle.rs`
(`#[derive(Serialize)]`, field names verbatim). There is **no `mode` field** — the
mode is a client-side choice. Ballots are flattened to `u64` pairs `(round, node)`;
values are only ever a `u64` `vhash` (never bytes). All derivations live in
`app/adapter.js`.

| JSON (array of…) | Fields | UI derives |
| --- | --- | --- |
| `protocol[]` | `kind` (prepare/promise/accept/accepted/nack/commit), `bround`,`bnode`, `slot`, `from`,`to`, `depart_ms`,`arrive_ms`,`latency_ms`, `outcome` | frames, particles, phase track, drop X marks |
| `node_states[]` | `time_ms`,`node`, `pround`,`pbnode`, `has_accepted`, `around`,`abnode`,`vhash` | per-acceptor promised + accepted@slot0 → node rings, swatches, single-decree inspector |
| `chosen[]` | `time_ms`,`node`,`slot`,`vhash` | chosen diamonds, "chosen by k/3", per-slot value colour |
| `leaders[]` | `time_ms`,`node`,`round` | multi leader column + badge, ballot trail, failovers |
| `applied[]` | `time_ms`,`node`,`slot` | multi committed-prefix high-water |
| `crashes[]` | `time_ms`,`node`,`seam` | crash ⚡ + seam tag |
| `restarts[]` | `time_ms`,`node` | restart ↻ |
| `syncs[]` | `time_ms`,`node`,`sync`,`writes` | fsync'd vs relaxed batches (digest) |
| `recovered[]` | `time_ms`,`node`,`slot`,`vhash` | durable read-backs (recovery badge) |
| `compactions[]` | `time_ms`,`node`,`first` | log truncation floor markers |
| `snapshots[]` | `time_ms`,`node`,`chosen_index`,`first` | snapshot-install blocks + prefix jumps |
| `catchups[]` | `time_ms`,`from`,`to`,`kind`,`from_slot?`,`first?`,`last?`,`count` | commit-replay catch-up arrows + fill highlights |
| `reads[]` | `client`,`seq`,`issued_ms`,`done_ms`,`read_index?`,`attempts`,`outcome` | read markers at the commit barrier |
| `read_confirms[]` | `time_ms`,`node`,`read_index?`,`served_index?` | leader-side confirm rounds (digest) |
| `disk_faults[]` | `time_ms`,`node`,`record`,`kind`,`persisted` | disk-fault badges + fsyncgate split |
| `storage_crashes[]` | `time_ms`,`node`,`error` | storage crash-decision ⚡ + down windows |
| `corruptions[]` | `time_ms`,`node`,`record`,`kind` | silent-rot badges (ground truth) |
| `detections[]` | `time_ms`,`node`,`slot`,`case` | checksum-mismatch flags |
| `repairs[]` | `time_ms`,`node?`,`kind`,`record?`,`slot?` | heal ✓ / wait ❚❚ / reset / unrecoverable marks |
| scalars | `seed`,`requests`,`delivered`,`dropped`,`ticks`,`longest_rtt_ms`,`sim_duration_ms` | digest / captions |

Quorum counts, dueling, leader trail, phase-1-vs-phase-2, and the oracle badge are
all *computed client-side* from the above (no dedicated fields). A run only exists
if the sim didn't panic, so the oracle badge is green by construction — surfaced to
make the guarantees legible.

## Proposed contract changes (additive only — not implemented here)

These would enrich the multi inspector; v1 renders correctly without them.

1. **Per-slot per-acceptor accepted snapshots.** `node_states` carries accepted
   state for slot 0 only. A full multi inspector wants `Slot → (Ballot, vhash)` per
   node over time — e.g. a new `log_states[]` stream, or an optional per-slot map on
   `NodeStateShot`. Until then the multi inspector shows role / committed index /
   chosen-per-slot and notes the gap.
2. **Explicit node role per observation** (`Follower`/`Candidate`/`Leader`) on
   `NodeStateShot`. Role is currently *inferred* from `leaders[]`; an explicit field
   would let the inspector show Candidate precisely.

## Fonts

The design system asks for IBM Plex Sans (UI) and IBM Plex Mono (all protocol
state). `build-wasm-demo.sh` stages the woff2 best-effort: from `PLEX_WOFF2_DIR`
if set, else from `nixpkgs#ibm-plex` — which ships OTF only, so each face is
converted with `woff2_compress` (`nixpkgs#woff2`). If staging fails the build
still succeeds: the `@font-face` block is stripped from the *staged* index.html
(the `plex-fonts` markers) so the book never 404s, and the CSS falls back to
`system-ui` / `ui-monospace` — the mono-vs-sans distinction (the load-bearing
teaching cue) survives; only the exact Plex glyphs are lost.
