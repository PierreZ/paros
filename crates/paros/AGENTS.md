# paros

The library: `pub use paros_core::*` plus everything that does I/O — the provider-generic
drivers for the four roles, the storage seam and its stores (in-memory and the durable
`journal`), the RPC contract, the client (`paros::client`) and the system journals' folds
(`paros::system`). Written once over moonpool's `P: Providers`; the same code runs in
production (`parosd`) and in simulation (`paros-sim`). Stack: `paros-core` ← **`paros`** ←
`paros-sim` ← runner; `paros` ← `parosd`. Stays wasm-checkable and provider-free.

## Map

- `driver/mod.rs` → `run_node`, `run_journals`, `RunError`, `BootKind` → the node loop; one journal or a static list (#188); `run_journals` takes `machine: Option<CellMachine>` (a founding member serves its decree answers, #277; an admitted machine its machine contract, #474) and starts or stops each journal placed on the node from the registry's bookings (#474 (journals on admitted machines)); `Reconfigure` and `Retire` name their journal.
- `driver/journals.rs` → `JournalStores` (`opened`: a store passed its boot, #208; `node_audit`: the node's own facts, #243), `SingleStore` → per-journal runtime and quarantine (`quarantine_ticks`).
- `driver/system.rs` → `ControlPlan`, `ControlFollower` → the control journals' follower: the registry and every hosted tenant's control journal (#189, #210); `run_journals` starts and stops journals from their events. A seed the fold sees registered elsewhere is dialed there (`reseed`), and an admitted machine's node loop moves its seeds and their lanes to a book offered to its cache (`adopt`, #505 (stranded admitted machine)).
- `provision.rs` → `provision_store`, `provision_matchmaker_store`, `Provisioned` → format a store ahead of its first start; an interrupted run resumes from the disk (#208).
- `driver/{boot,ready,report}.rs` → format-marker check, the `Ready` I/O side in persist-before-send order, boot report.
- `address.rs` → `Address`, `Names` → a machine's advertised `HOST:PORT`, kept as written (a literal or a name), and the one resolver its dialers share; a name is resolved at dial time (#257).
- `driver/transport.rs` → `PeerMailbox`, `LaneOpener`, `peer_address`, `peer_target`, `PeerTarget` → keep-newest lanes per journal, round-robin; a lane's `Dialer` resolves its peer's name before a batch and forgets it after a failed delivery (#257); it dials the peer's machine interface the registry holds, aimed at the resolved address, else the well-known `Deliver`, and falls back to the well-known one after the interface refused a delivery for good (#404).
- `driver/{matchmaking,handover,operator,events}.rs` → matchmaker wire (`MatchmakerLinks`: a link to each registered machine is added at its admission, #501 (matchmaker sets off the founders)), set handover (`ReconfigureMatchmakers` names its tenant; its bootstrap paged by `registry_page`, #439), Reconfigure/Retire/Inspect, events.
- `driver/edge.rs` → `RpcEdge`, `NodeInbox`, `ReplicaInbox`, `MatchmakerInbox` → the inbound edge, polled as a `select!` arm; it serves and dials with the role's `Transport`.
- `transport.rs` → `Transport` (`Plaintext`, `Tls` with feature `tls`), `RuntimeFuture` → how a runtime's sessions travel (not the peer lanes of `driver/transport.rs`); a parameter of every listening driver and a field of `FrontendSettings`; `client_only` builds a client runtime (parosctl, the sim's clients) (PR #509 (mutual TLS)).
- `tls.rs` (feature `tls`, off by default so the crate stays wasm-safe) → `Role`, `identity` (`spiffe://<universe>/<role>/<name>`), `leaf`, `SERVER_NAME` (`paros`, every serving leaf proves it, every client expects it), `ClientCertificates`, `Material`, `Files` (the three PEM files, all or none), `serving`, `dialing`, `ProviderUtc` → moonpool-rpc's TLS and certificate authority (moonpool #330 (mutual TLS)); `parosctl tls` and the sim issue with the same `leaf`.
- `driver/reply.rs` → `answer`, `match_answer`, `maybe_duplicate` → the one client-reply seam.
- `driver/calls.rs` → held `Write`/`SetLeader`/`Truncate`, answered with the verdict their slot folded to (#204).
- `driver/log_reads.rs` → `JournalReads`, `ReadLimits` → the public `Read`: quorum-confirmed, served from the fold, its page cut to `max_read_records`/`max_read_bytes` and its tail wait to `min_wait_ms..=max_wait_ms` (#241).
- `driver/config.rs` → `DriverTunables` → every driver cadence/budget (`partition_move_resends`: a grid round re-sent that often moves to the next column, the budget doubled per move up to 64 times (`move_budget`), `move_stuck_rounds` in `driver/mod.rs`, #533 (move a stuck round)) (the cell election's lease, renewal and compaction bound too, #240; a machine's own clients, `internal_client()`, and the `Resolve` answer bound, #457 (hard-coded tunables)); `default()` is the sim's baseline · `driver/tunables.rs` → `DriverTunables::production`, `check_floors`, `BelowFloor` → the shipped profile and the floors (#209).
- `scenario.rs` → `WITHHOLD_GC`, `HOLD_JOURNAL`, `LOSE_VERDICTS`, `LAG_FOLLOW`, `STALL_PROXY` (a proxy drops the acceptors' answers, #341), `RESIGN_DELEGATING` (a leader that holds delegated rounds resigns and campaigns again, #341), `ADMIT_LATE` (half the nodes, drawn at boot, admit the registry's pool 2 s late, #387 (unpooled joiner)), `HAND_OFF` (a transferable leader hands off on about a third of its beats, #484 (silent driver fault sites)) → the named BUGGIFY locations a harness forces per seed (`buggify_named!`, `set_activation`, #318 E). Every other choice is an inline `buggify_fault_with_prob!` (send seam `driver/transport.rs`, reply seam `driver/reply.rs`, picks and handoff `driver/mod.rs`, #318), a grid leader that tears one slot's Phase-2 column and resigns (`tear_column` in `driver/ready.rs`, #396), and one plain `buggify_with_prob!` that stays on in the recovery tail: an acceptor about to overwrite a different value campaigns first (`contest_overwrite`, #376), once per `(slot, held value, incoming value)` (`JournalRt::contested`, #396). The durability moments are inline `hint!`s in `driver/ready.rs`, `driver/mod.rs` (a journal re-opened after its quarantine, before its next sync, #348), `matchmaker/mod.rs`, `replica_tier/mod.rs` (#297) and the journal stores (#294).
- `audit.rs` → `Audit`, `NoAudit` → the observation port; `call_received` and `call_answered` report each data-plane call a machine counts, only while it records metrics (#366 (metrics)).
- `metrics.rs` → `Metrics` (`off`, `on`; `registry`, `families`, `render`, `ready`, `usage`), `CallKind`, `CallOutcome`, `Family`, `FamilyKind`, `Phase`, `JournalUsage`, `Totals` → a machine's metrics in a plain `prometheus` registry (#366 (metrics), §3.6): counters and gauges only, no histogram (decided on 2026-10-15); calls, answers by outcome and their seconds, bytes per call and journal, the applied and chosen slots, the settles and their seconds, the busyness window, its heartbeat and the phase; observation only, never read by the code that serves; a journal's labels are its names and its ids in hex. `metrics/tests.rs` pins them.
- `driver/metered.rs` → `Meter`, `journal_names` → the node loop counts each `Write`, `Read`, `SetLeader` and `Truncate` where it takes it, and times and counts the answer by outcome (`write_answer`, `read_answer`, `set_leader_answer`, `truncate_answer`) through `ReplySender::observed` (`rpc/inbound.rs`); `Shared::settle` records the settle time and the slots.
- `storage/mod.rs` → `LogStorage`, `StorageError`, `StorageRecord`, `WriteOutcome` → the async seam.
- `storage/mem.rs` → `MemStorage` · `storage/contract.rs` → `storage_contract_suite`.
- `matchmaker/{mod,storage}.rs` → `run_matchmaker`, `HostedSet`, `Host`, `SetOpener`, `MatchmakerStorage`, `MemMatchmakerStorage`, `Registrations`, `matchmaker_storage_contract_suite` → one matchmaker set per tenant, one registry per journal inside it (#190); a request names its tenant, its journal and the matchmaker it addresses (a misaddressed one is dropped); `Host` is the loop, fail-stop for a matchmaker process, closing only the set on a machine; the driver reports what a commit has in flight (`Audit::matchmaker_in_flight`).
- `proxy/mod.rs` → `run_proxy`, `ProxyConfig`, `ProxyJournal` → Phase-2 subset, nothing durable (#142); one `ProxyLeader` per journal, demuxed by `JournalIdentifier`, each journal's facts to its own audit port (#193).
- `replica_tier/mod.rs` → `run_replica` → learner subset over a `LogStorage` per journal, opened through `JournalStores`; one `ReplicaNode` per journal, serves `Read` per journal (#144, #193); a storage fault on any journal restarts the replica.
- `rpc/methods.rs` → one `RpcMethod` per call, `WellKnownMethod` ids (public `0x5041_00xx`, internal `0x5041_01xx`, matchmaker `0x5041_02xx`, machine `0x5041_03xx`: `Identify`, `FormCell`, `CellInit` `0x5041_0304`, `PrepareCell` `0x5041_0305`, `Admit` `0x5041_0306`, `Register` `0x5041_0307` (#349) and `JournalRequest` `0x5041_0308` (#210) (method ids only: served in the `CoordinatorInterface` group, #404), `View` `0x5041_0309` (#399), `Resolve` `0x5041_030A` (#216), `Load` `0x5041_030B` (#424), `CapacityRequest` `0x5041_030C` (#476 (tenant footprint), served in the `CoordinatorInterface` group); `0x5041_0303`, the old `Init`, is retired; frontend `0x5041_04xx`: `FrontWrite`, `FrontRead`, `FrontTruncate`, `FrontSetLeader`, answered with the plain acks, #192 (the frontend), and `FrontSetJournalTags` `0x5041_0405` (#575 (key:value tags)); retired ids never reused). Two dynamic groups (#404 (static vs dynamic endpoints)): `MachineInterface` `0x5041_1001` (`Deliver`, the three matchmaker calls and the six data-plane calls, one per founding member's incarnation; each keeps its well-known endpoint too) and `CoordinatorInterface` `0x5041_1002` (`Register`, `JournalRequest`, `CapacityRequest`, one per coordinator term).
- `machine/mod.rs` → `MachineFacts`, `CellPlan`, `Class`, `ControlJournals` (the cell's, the election journal, the fleet's, one type for driver and client, #243, #240) → a machine's facts (no peer: a machine is configured with none, #277) and its cell's plan, the value of `cell init`'s decree (every identifier drawn by the machine that drives it).
- `machine/lifecycle.rs` → `run_machine`, `MachineSettings`, `MachineAddresses`, `MachineError` → the whole machine lifecycle `parosd` and the simulation run (#246): format (mint `node_id`), the amnesia and class checks, wait (an acceptor of any `cell init` that lists it), serve the plan and keep answering the decree; it binds the listen address and advertises the other (`MachineAddresses`, #257: a wildcard listen address with no advertised one is refused), and dials through the caller's `Names`; the disk is a bare `ProviderDisk` over the caller's provider and the audit port is the caller's (`AuditScope`, #294); a late boot is an inline `buggify_range!`; a failed record read or write is `MachineError::Storage`, a restart, never a refusal.
- `machine/pin.rs` → `AdminPin` → the bootstrap pin (#245 (Biscuit tokens)): an idle machine checks an `admin` token on `CellInit`, `PrepareCell`, `FormCell` and `Admit` through an `Authz` at its epoch plus the provider's time; open by default; a refusal answers `invalid_token`, `expired` or `forbidden`.
- `machine/wait.rs` → `wait_for_cell`, `CellLedger` → the idle machine (#196, #216, #277): `Identify`; `PrepareCell` and `FormCell` as an acceptor of the cell decree (accepting is forming: `format`, then the vote; a `hint!` after the durable promise and one between the format and the vote, #246, #294); `CellInit` as its proposer over the founding members, every one an acceptor: all answer Phase 1, a majority chooses (#246: a wiped member stays a dead member of the plan; `cell_lost` once a majority is wiped) (adopt a reported plan, else draw one; form the others, then itself; a vote for another list's plan is another cell's, never adopted, #216).
- `machine/admitted.rs` → `AdmittedMachine` → a machine `cell add-machine` admitted (#216): serves `Identify` (with its newest registry fold's `registry_position`, #505 (stranded admitted machine)) and a node-only `Inspect` with its cell, acks `Admit` into its own cell as `in_cell`, so `cell add-machine` reports no `Admit` stage it did not record (an admission that landed between its `Identify` and its `Admit`) (adopting its book into the cache when it is taken past its own fold and names other machines, #505), refuses the cell decree (`in_cell`, so `cell init` is `cell_exists`); it runs the node loop and serves the journals placed on it, following the control journals through the founding members (#474). `Admission` (in `machine/mod.rs`) is what `Admit` carries and the record keeps (`admitted`, `control`, `fleet`, `peer`, `founder` lines).
- `machine/coordinator.rs` → `serve_term`, `TermDuty`, `Watch`, `election_tunables` → the cell coordinator (#240): every founding member campaigns in a task beside its node loop (seed and BUGGIFY decisions drawn on the loop: a stalled leader, a hand-off; a term-ending decision is a fault, never fired in the recovery tail, `chaos`); a won term installs its uuid on the cell control journal, folds it, finishes in-flight admissions and joins the cell to the universe (`machine/universe.rs`), then publishes the interface, renewing whenever a renewal falls due while each duty runs (`renewing`; a slow install is a BUGGIFY decision, #542 (coordinator starves its lease while it installs)); a lost install resigns; a term that could not claim dials the founders where the registry holds them next (`follow_book`, a renamed founder, #529). For the rest of a served term its `Watch` (#211, D6) `Identify`s every founding member and registered machine at each renewal period and writes changes only: a new incarnation of a registered machine registers again, `MachineUp` for one held down or seen as another incarnation, `MachineDown` after `machine_down_after` of silence, `MachineAdmitted` once for a registered machine that answers with this cell's id (#511), `Admit` again with the cell's book and its fold's position to an admitted machine whose reported `registry_position` stopped below the coordinator's fold (`CellSession::readmit`, #505 (stranded admitted machine)), and it releases the slots of every tenant the cell dropped (#212 (placement)); the term's first write that does not land ends the watch (never fight an admin session's fence). A served term registers a `CoordinatorInterface` group (#404) serving `Register` (#349) and `JournalRequest`, publishes its reference with the address, and drops it when the term ends (a BUGGIFY decision keeps it one more step, answering `not_coordinator`): the term's coordinator `Identify`s the machine at the address it asks for and writes `RegisterNode` when the registry holds another address, name or machine interface. A served term answers `JournalRequest` as the tenant coordinator (`machine/tenants.rs`, #210). `Audit::call_observer` hands a harness the coordinator's calls.
- `machine/universe.rs` → `joining`, `tenant_steps`, `follow` → the cell's side of the universe (#513 (fleet Init duel), #225): at its install and at each watch round the coordinator reads the universe directory; once it holds this cell and its control journal, the coordinator writes `JoinFleet` with the directory's fleet id, then, for each `users` tenant of the cell `REGISTERING` and neither hosted nor dropped, its birth footprint (`GrantCapacity`; a refusal only once every founder registered, #476 (tenant footprint)) and `HostTenant` once it is granted, and `DropTenant` for each one `REMOVING` and not dropped; `init` and a tenant's creation or removal wait for these writes and never claim the cell control journal.
- `machine/cache.rs` → `CachedRegistry`, `CacheSink`, `spawn_writer`, `starting_book` → the durable cached registry fold (#211): the cell's address book at one registry position, in the file `registry` beside the record; written forward only by a task beside the machine; read at every start, so a machine dials moved machines where the cache says (a hint: a wrong address costs liveness only).
- `machine/follow.rs` → an admitted machine folds the registry through the machines it knows each renewal period and offers each new book to its cache (#211); a book offered past its own position (an adopted `Admit`, #505 (stranded admitted machine)) is the book its next read dials.
- `machine/resolve.rs` → `Resolver` → `Resolve` (#216, §3.5): every machine of a cell, founding or admitted, answers "which references serve tenant T" in a task of its own, from folds of the universe directory (the tenant's id, control journal and cell, with `universe_id` and the universe's and cells' names, #239; `tenant_in` judges the name) and the registry (the cell's machines, `cell_book`), kept between requests and read through the cell's machines like a client, each machine answered with the interface the registry holds (#404); each answer bounded by `DriverTunables::resolve_answer_within`, and an answer cut short keeps what its folds read (#457 (hard-coded tunables): a reset to position 0 never answered again once a fold outlasted the bound); one BUGGIFY decision drawn at spawn answers every request from fresh folds.
- `machine/book.rs` → `address_book`, `cell_book` → the cell's address book (#349): the founding members at the address the registry holds for them, else the plan's; `cell_book` adds every registered machine not retired.
- `machine/register.rs` → the machine-to-coordinator request path (#349): on every start a formed or admitted machine reads the election journal for the coordinator's published interface (`client::journals::Coordinator`: the address and the term group's reference, #404) and sends it `Register` with the address it advertises now and its machine interface, again each renewal period until the registry holds it; it reads the election from its peers, never its own node while it has peers, from a first peer a BUGGIFY decision draws, and a round that finds no coordinator starts from the next peer (#479 (renamed founder not registered)). Its receiver ends a moved founding member's hold: the node loop beats no journal (#390) and the member does not campaign for the cell coordinator (#506 (renamed founder not registered)) until then.
- `driver/book.rs` → `PeerBook` → a founding member folds its own copy of the cell control journal after each tick (each peer's address and machine interface, #404; a fresh interface may be held back one fold, a BUGGIFY decision), from its cached registry fold's addresses on (no lane moves below the cache's position, and each later book is offered to the cache, #211); a peer the address book moved is dialed at its new address from its lane's next batch on (`PeerMailbox::readdress`, #349).
- `machine/formed.rs` → `FormedCell` → a formed machine answers the decree (`PrepareCell`, `FormCell`, `Identify`) from its record while it serves its cell (#277), and teaches it (`Teacher`, the decree's learner catch-up): each election renewal period it `Identify`s the other members of its plan and re-sends its vote as `FormCell`, with the operator's token that formed it (`FormedCell::token`, `FormationToken`: in memory only, never in the record; none after a restart, so no teaching), to one that answers idle, until each member formed, answered as another machine, refused the token, or moved to another address in the cell's address book (the cache's offered books).
- `machine/matchmakers.rs` → `SetBookings` → a storage machine's matchmaker host (#190): the shipped matchmaker loop in a task on the node's edge (`JournalStores::host_on_edge`), every tenant's set born on the founding members (`CellPlan::matchmakers`), a set provisioned at its first request and recorded in the disk's `sets` file (the commit point; a `hint!` between the format and the record); a machine that is not a founding member provisions only a set the registry books on it (`JournalStores::book_sets`, #501 (matchmaker sets off the founders)), and a released set stays open, frozen, for the successor chain.
- `machine/modes.rs` → `Modes` → the tenant coordinator's mode changes (#214 (tenant modes)): one step per watch round, after the move step, in turn over the live journals whose recorded placement (`TenantJournal::placed`) is not their desired shape on exactly their slots (a journal with a slot on a draining machine is the move's): book the slots the mode lacks (a `hint!` after it), reconfigure the leader onto the new members under the new quorum system (a smaller mode keeps the slots placement does not release), then, once in force, record `Placed` and, once the leader's GC watermark reached it, release the slots of the members it left (it retires none: a later mode may place the journal on that machine again); a later term finishes a change an earlier one started.
- `machine/sets.rs` → `Sets`, `SET`, `set_of` → the tenant coordinator's matchmaker sets (#501 (matchmaker sets off the founders)), sized `2F+1` from the tenant's largest `failures_per_partition` (at least 1, at most every storage machine placement may book, #214 (tenant modes)): one step per watch round, in turn over the hosted tenants but the cell's: book the slots a set lacks with `paros::placement` (`Role::Matchmaker`; a set born on the founders holds none, so it is placed the first time), hand it over onto the booked machines that stay through a founding member (`ReconfigureMatchmakers` names its tenant), then release every slot on a draining machine once the set in force (the founders' latest belief for the tenant's control journal) is those machines (a `hint!` after a booking; the first term that advances a move may resign, the same BUGGIFY decision as a journal move's). With none pending, a settled set is judged again in turn: a node that finishes a frozen generation proposes the members that answered its freeze, so a set can leave its booked machines after its move; a term's first finished move asks its handover again on a BUGGIFY decision of the candidacy (a late retry).
- `machine/record.rs` → `MachineRecord`, `journal_config` → the machine record's text (identity, class, capacity, zone and rack; the decree's acceptor state: `promised <round>/<node>` and the vote `plan <cell_id> <round>/<node>`, written after the stores, the commit point) and a plan journal's `Config`.
- `machine/disk.rs` → `ProviderDisk` → the record's atomic rewrite (staged, synced, renamed, every directory on the way synced), the amnesia probe and the formation's stores over any `StorageProvider`: `parosd` and the simulation both hand it to `run_machine` bare (#246, #294).
- `machine/stores.rs` → `AuditScope`, `MachineStores` → a formed machine's `JournalStorage` per plan journal, an existing member's; a journal a tenant created is provisioned at its first open (`provision_store`, then the record's `created` line, the commit point), then boots as an existing member (#210).
- `machine/tenants.rs` → `TenantDesk` → the tenant coordinator for one term (#210): claims each tenant control journal under the term uuid, catches the cell's fold up at every request so a dropped tenant is refused by every term (#395), writes `Describe` once, answers a request from its recorded outcome or writes it (id drawn from the candidacy's seed; a reused id on a BUGGIFY decision of the node loop). A create is placed over the cell's storage machines, founding or admitted, with `paros::placement` (#474), and its acceptor slots are booked through the term's cell session before it is written; a create with no slot is recorded `Unplaceable`; a delete's slots are released after its tombstone, and slots no live journal holds by the next create in the tenant; a term's first create is abandoned after its bookings on a BUGGIFY decision (#212 (placement)). A write past the fold is caught up, and a catch-up that falls short answers `unavailable` (#445 (ignored load result)); an impatient term, a BUGGIFY decision of the node loop, stops listening at once on its first create and its first catch-up.
- `machine/capacity.rs` → `grant` → the cell coordinator's answer to a `CapacityRequest` (#476 (tenant footprint)): a decided id answered from its record, a tenant the cell neither hosts nor booked refused `unknown_tenant`, else the grant (ids drawn from the term's desk) or its refusal written in the cell control journal; the tenant desk books a create's acceptors through it.
- `machine/footprints.rs` → `Footprints` → one footprint step per watch round, after the set step, in turn over the tenants with a granted footprint (#476 (tenant footprint)): `paros::footprint::fix`, written through the term's cell session; first, the cell tenant's and the universe tenant's footprints, which `init` never books (never refused).
- `machine/moves.rs` → `Moves` → the tenant coordinator's moves off draining machines (#474 (journals on admitted machines)): one step per watch round, in turn over the journals with a slot on a draining machine: book a slot elsewhere (a `hint!` after it), reconfigure the journal's leader onto the machines that stay, then, once the leader's GC watermark reached the configuration in force, retire the old member if the leader's floor names it and release its slot; a later term finishes a move an earlier one started (the first term that advances one resigns on a BUGGIFY decision of the candidacy).
- `rpc/inspect.rs` → `InspectTarget`, `InspectRefusal` → what an `Inspect` asks for: a named journal or the node alone; an unset identifier is refused (#243).
- `rpc/inbound.rs` → `Inbound` (`in_group`: a founding member serves a method in its machine group too, both streams one queue, #404), `ReplySender`, `serve_deliveries`, `rpc_config`, `MAX_FRAME_BYTES` → a `Deliver` batch whose `cell_id` is not the receiver's is refused whole (`EdgeRejection::ForeignCell`, #216); the sender stamps its cell on every batch (`driver/transport.rs`, `LaneOpener::cell_id`; `0` without a cell plan). The matchmaker requests carry it too (`rpc::Addressed`, stamped from `MatchmakerLinks::cell_id`): a matchmaker host refuses another cell's request before it seats a set (`Host::admitted`, #539 (matchmaker cell fence)).
- `rpc/client.rs` → `NodeClient` (one at-most-once attempt per call; `named` resolves its `Address` per call, #257; `with_interface` sends the data plane through a machine interface, never falling back on its own, #404; `frontend` sends the four journal calls as the `Front*` methods with a `Pass`, #192 (the frontend)), `Pass` (a token and the names the caller bound to local ids; a call by name sends unset ids), `MatchmakerClient` (follows the peer book's address and machine interface, and the well-known endpoint after the interface went stale, #404).
- `rpc/codec.rs` → shared scalar codecs (ballot, party, quorum system, config, command).
- `rpc/consensus.rs` → `Message` ↔ protobuf · `rpc/matchmaker_codec.rs` → matchmaker wire ↔ protobuf.
- `rpc/tests.rs` → round-trip tests; malformed input refused.
- `client/mod.rs` → `Client`, `ClientTunables`, `Retarget`, `LeaderHint` → policy loops: `write`, `resolve`, `read_any`, `journal_state`, `claim`, `set_leader`, `truncate`, `reconfigure*`, `inspect`, `retire`; `*_attempt` one-shot calls.
- `client/outcome.rs` → `WriteOutcome`, `ReadOutcome`, … → every reply judged once; a frontend's verdict first (`Denied(Denial)`, or `Unanswered` as `Ambiguous`, #192 (the frontend)).
- `client/writer.rs` → `Writer`, `leader_uuid` (a uuid per term derived from the caller's random seed, #241; `with_uuid` for an operator-named one; `truncate` carries the leader's fence, #228; `stale_entry` and `stale_truncate_request` are the explicit misbehaviours) · `client/reader.rs` → `Reader`, `ReaderOutcome::Gap`.
- `client/multi.rs` → `append_entry`, `append_request`, `open_truncate_request` → the unfenced calls of a multi-writer journal (#241): the unset leader uuid and `seq` 0; the library never re-sends one on its own.
- `client/observer.rs` → `CallObserver` (every attempt, and every `resolve` settlement: `resolving`/`resolved`, #444), `NoObserver` · `client/tests.rs` → the pure parts pinned.
- `client/checkpoint.rs` → `Checkpointable`, `Folder`, `Checkpointer`, `CheckpointRecord` (`MAGIC`, `Begin` / `Chunk` / `End`), `run`, `load` → checkpoint and truncate for any journal owner (#230): a checkpoint is a run of small records committed by its `End`, written in batches a node's `TooLarge` splits; a run with no valid `End` is never restored (#353); `Folder` is also the registry follower's fold.
- `client/bootstrap.rs` → `cell_init`, `InitOutcome`, `discover`, `majority_cell`, `CellServer` (the cell a majority of a list serve, #216, each server with the machine interface its `Inspect` gave, #404), `control_journals`, `control_journals_of`, `cell_members`, `identify`, `admit` → `parosctl init`'s calls: `cell_init(providers, rpc, target, members, patience)` sends `CellInit` to one founding member (#277); server ids and the control journals learned from a node-only `Inspect` (#196, §3.8, #243).

## Local rules

- **Faults are inline, in this crate** (root *Simulation rules*, #294). A new driver decision is
  an inline `buggify_with_prob!` / `buggify_pick!` at the line that makes it, consulted only where
  its answer is observable. A moment where a crash is interesting (staged not synced, durable not
  sent) is `hint!("label").await` at that line. Never add a hook trait (the deleted `DriverHooks`, `ClientHooks`, commit hooks), a `Seam`
  variant, or a store or disk trait whose only second
  implementation would be a sim wrapper. A path the code walks gets a `reachable!` probe, with
  the message the sim's gate already uses, never reworded.
- A new tunable is a `DriverTunables` field with a default (`driver/config.rs`) and a
  `buggify_knob!` in `paros-sim`'s `NodeShape`; a new durability boundary is an inline
  `hint!("label").await` with a `reachable!` on `Strike::Killed`.
- Every call is one at-most-once attempt (`try_get_reply`), never `get_reply`.
- `paros::client` draws no randomness: every choice is the caller's.
- Storage implementations pass both contract suites.
- Spans are non-optional (`#[tracing::instrument(skip_all, fields(..))]`); see root *Tracing spans*,
  *Audit doctrine*.
